이번 프로젝트는 내가 코드를 직접 짜는 게 아니라, **Claude(AI)한테 Unreal MCP + Blender MCP를 연결해서 프롬프트로 게임을 만들어 보는** 실험이다. 그래서 이 일지는 "내가 뭐라고 시켰고 → AI가 뭘 만들었고 → 그래서 내가 뭘 했는지"만 그대로 적는다.

## 0. 시작 전에 규칙부터 정했다

MCP 연결은 "해당 언리얼 프로젝트에 MCP를 연결하고 싶어"라고 하니까 AI가 플러그인이랑 설정 파일을 잡아 줬다. 나는 에디터 재시작만 했다.

그다음 작업 규칙을 먼저 던졌다.

> 1. MCP로 게임을 제작을 하되, 결정은 프롬프트 작성자가 권한을 가지고 있다
> 2. 게임에 모델이나 에셋, 애니메이션이 필요하면 작성자에게 요구하거나 추천해라
> 3. 개발 과정을 velog에 올릴 수 있는 형식을 만들어 놓을 것
> 4. 게임 기획은 작은 것부터 만들면서 확장하는 형식으로 하기에 거시적으로 물어보지 말 것

AI가 몇 가지를 되물어서 이렇게 답했다.

- 처음부터 크게 만들 생각 없다. 내가 만들고 싶은 기능부터 만든다
- 임시 구체로 시작하지 말고 **처음부터 Blender MCP로 모델을 만들자** (나중에 교체할 때 아쉬워서)
- C++ + 블루프린트 혼합으로
- 백업은 GitHub 레포에 .gitignore, .gitattributes 잡아서 자동으로 푸쉬

## 1. 첫 기능: 다가가면 말 걸 수 있는 NPC

### 내가 쓴 프롬프트

> 일단 기본적인 NPC를 만들거야 1인칭 게임이고 NPC에게 다가가면 상호작용이되면서 대화가 가능하게

AI가 세부 사항을 선택지로 물어봐서 이렇게 골랐다.

- 상호작용: **E키**
- 대화: **선택지 포함**
- 캐릭터: **판타지 – 떠돌이 상인**
- 애니메이션: **리깅 + Mixamo 대기 모션**
- 1인칭: **카메라만** (팔 없음)

### AI가 만들어 준 것

**Blender로 상인 모델.** 챙 넓은 모자, 흰 수염, 녹색 튜닉, 붉은 망토에 냄비랑 랜턴 달린 큰 배낭까지 붙여서 로우폴리로 만들었다. Mixamo에 올릴 수 있게 T포즈로 뽑아 줬다.

![Blender로 만든 상인](https://media.githubusercontent.com/media/Choc1015/NPCProject/main/Docs/Devlog/images/01_merchant_blender.png)

**언리얼 쪽.** AI가 C++ 클래스(상호작용 컴포넌트, 대화 데이터, 대화 컴포넌트, NPC, 플레이어, HUD)를 짜고, MCP로 입력 에셋, HUD 위젯, 상인 블루프린트, 대화 데이터, 테스트 맵까지 만들어 줬다. 대화는 "인사 → 선택지 3개(물건/어디서 왔는지/작별) → …" 식으로 갈라지게 들어가 있었다.

### 내가 한 것

**Mixamo 작업은 내가 했다.** AI한테 방법을 따로 설명해 달라고 해서 그대로 따라 했다.

- AI가 뽑아 준 FBX를 Mixamo에 올려서 자동 리깅 (손가락 없는 장갑이라 **No Fingers**)
- 대기 모션 `Breathing Idle`이랑 대화 모션을 받아서 프로젝트 폴더에 넣었다
- "대화용 애니메이션까지 설정해놓았고 에디터는 닫았어" → AI가 C++ 빌드하고 임포트까지 해 줬다

## 2. 문제: 상호작용 안내가 안 뜬다

### 내가 쓴 프롬프트

> 대화 상호작용이 안보여

### AI가 찾은 원인과 수정

상인을 정면으로 봐도 `[E] 대화하기`가 안 떴다. AI가 찾아보니 상호작용 감지에 쓰는 채널을 캐릭터 기본 충돌 설정이 무시하고 있었고, Mixamo 메시엔 충돌체도 없어서 감지가 한 번도 안 맞고 있었다고 한다. NPC 캡슐이 그 채널을 막게 고치고 상인을 다시 배치했다.

### 내가 한 것

플레이해 보고 "잘 돼"라고 했다.

![상인 앞에서 뜨는 상호작용 안내](https://media.githubusercontent.com/media/Choc1015/NPCProject/main/Docs/Devlog/images/01_interact_prompt.png)

## 3. 문제: 대화하면 상인이 드러눕고, 모션이 계속 반복된다

### 내가 쓴 프롬프트

> 대화를 시작하면 상인이 누워진 상태가 돼 아마 애니메이션이 기본 모델과 pitch가 90도 다르게 뽑힌거 같은데 확인해주고 대화 애니메이션이 계속 반복되는게 조금 별로야 내가 withskin으로 대화 애니메이션을 2개더 줄테니 3개가 적절하게 섞여나오게 만들어줘 대신 애니메이션 loop는 빼주고

### AI가 찾은 원인과 수정

처음에 대화 모션을 Without Skin으로 받았더니 임포트가 안 돼서, AI가 Blender에서 모션을 메시에 옮겨 붙여서 다시 뽑았었다. 그 과정에서 축이 90도 돌아간 거였다. 그래서 Blender를 거치지 말고 With Skin으로 받은 걸 바로 쓰기로 했다.

### 내가 한 것

- 기존 Talking 애니메이션을 지우고 With Skin으로 대화 모션 **3개**를 새로 받아 넣었다
- AI가 루프 빼고 대사마다 3개 중 하나를 랜덤으로 틀게 바꿨다

## 4. 문제: 모션이 뚝뚝 끊긴다 → 몽타주로 해 달라고 했다

### 내가 쓴 프롬프트

> 애니메이션이 대화를 선택할때마다 또는 한 애니메이션이 끝날 때마다 뚝뚝 끊기면서 다시 돌아가 이렇게 하지말고 몽타주를 이용해서 기본 idle과 talk애니메이션들이 자연스럽게 이어지게 해줘
> 예) idle -> talk1 -> idle, talk1->(대화 선택 시) -> talk2 -> idle

### AI가 만들어 준 것

애님 블루프린트에 `Idle(루프) → 슬롯` 구조를 만들고, 대사마다 대화 모션을 몽타주로 그 슬롯에 틀게 바꿨다. 모션이 바뀔 때랑 끝날 때 블렌딩이 들어간다.

### 내가 한 것

- AI가 MCP로 만든 애님 블루프린트는 스켈레톤이 비어서 상인이 바닥에 구겨졌다. AI가 "이건 직접 만들어야 한다"고 해서 **스켈레톤 우클릭 → Create → Anim Blueprint로 내가 만들었고**, 그래프는 AI가 채웠다
- 플레이해 보니 넘어가는 건 자연스러운데 **좀 빨랐다.** 그래서 "해당 수치는 내가 조정하려고 하는데 뭘 조정하면 될까?"라고 물었다
- AI가 상인 블루프린트의 `TalkBlendInTime`, `TalkBlendOutTime`이라고 알려 줘서, **블렌드 시간은 내가 직접 맞췄다**

## 느낀 점: AI는 내가 아는 만큼 잘 만든다

처음엔 AI한테 "대화 애니메이션 3개를 랜덤으로 섞어서 넣어 줘"라고만 했다. 넣어 주긴 했는데 모션이 바뀔 때마다 뚝뚝 끊겨서 **전혀 자연스럽지 않았다.** 요청한 기능은 돌아가지만, "자연스럽게"까지 알아서 챙겨 주진 않았다.

그런데 나는 언리얼에 **몽타주**라는 기법이 있다는 걸 알고 있었다. 그래서 "몽타주를 써서 idle과 talk가 자연스럽게 이어지게 해 줘"라고 기준을 잡아서 다시 요청했더니, 그제야 자연스럽게 이어졌다.

결국 **AI한테 맡기더라도 내가 어느 정도 지식을 갖고 있어야** 더 좋은 결과가 나온다. 어떤 기법이 있는지, 어떤 방향이 맞는지를 내가 알고 있으면 AI한테 정확한 기준을 줄 수 있고, 그만큼 결과물의 질이 올라간다. AI는 내 지식을 대신하는 게 아니라, 내가 아는 걸 더 빠르게 만들어 주는 도구에 가깝다.
